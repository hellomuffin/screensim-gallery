The action space and grounding rule

An action is a pair a = (v, γ): a motor verb and a grounding expression. The grammar is the contract between guidance and execution: an utterance maps one-to-one onto a finger motion, resolution is deterministic and purely lexical / geometric, and every failure mode is a typed, spoken refusal rather than a guess. Resolution is a pure function of (utterance, visible widget scene); identical inputs resolve identically, which is what places the action space inside the engine's replay-hash guarantees.

4 · Target scoring

A widget’s haystack is H(w) = subtok(N(label ⊕ sub ⊕ hint)), where subtok additionally splits tokens on [-_.] so “CoffeeBar_Guest” answers to “guest”. With query Q = N(τ) and distinctive part D = Q∖G:

           ⎧ 0.55 · 𝟙[τ substring of H(w)]                  if Q ∩ H(w) = ∅
base(τ,w) = ⎨ |Q ∩ H ∩ D| / |D|  +  0.1 · |Q ∩ H ∩ G|          if D ≠ ∅        (1)
           ⎩ |Q ∩ H| / |Q|                                  if D = ∅

s(τ,w) = base + 0.5·𝟙[N(label) = Q]  +  0.15·𝟙[Q ⊆ N(label)]
       − min(0.1, 0.03·|H ∖ Q|)                                            (2)

Constants: acceptance threshold θ = 0.3; tie band and every guard margin δ = 0.15; relation-anchor threshold 0.6; swipe-anchor threshold 0.5. The direction of the containment matters: every distinctive word uttered must appear in H(w) — the speaker may omit any part of the label but may not introduce words absent from the screen.

5 · Resolution procedure

Candidates C = {w : visible(w) ∧ interactive(w)}, i.e. the resolver sees exactly what the user sees. Rules apply in order; s* denotes the best accepted score in C.

ruledefinition
R1 pointp given → hit-test; smallest containing widget wins; none → legal no-op tap
R2 relationanchor a = first visible w with s(anchor, w) ≥ 0.6; C ← {w ∈ C : relr(a,w)}; empty → refusal
R3 type referenceif Q ⊆ G ∪ T and no visible label contains Q: filter C by kind(T); select by ordinal, else nearest to a by |Δcy|, else region, else uniqueness; several → ambiguity refusal. A phrase that names an actual label (“Switch Control”) never enters this rule
R4 scorekeep {w : s(τ,w) > θ}; if empty and a region was applied, rescore against the pre-region candidates (region = preference)
R5 hidden guardmaxw hidden, interactive s ≥ s* + δ → refuse “not on screen yet — try scrolling”
R6 prose guardmaxw visible, ¬interactive s ≥ s* + δ → refuse “just text, not something you can tap”
R7 near-ties{w : s ≥ s* − δ} with |·| > 1 → ordinal pick, else unique region member, else ambiguity refusal carrying the candidate count
R8 committop-scored widget; tap point = bounds centre

8 · Empirical robustness

Protocol: over six probe screens, an independent generator (Gemini) produced 144 in-vocabulary commands with declared targets — exact, partial, ordinal, regional, relational and filler-laden phrasings — and 48 out-of-vocabulary commands (synonyms, function descriptions, appearance) that a strict grounder must refuse. The action-space contract

Every reachable state takes every action to either a correct rollout or a reasoned refusal — never a silent no-op, never a generic error, never an effect that contradicts the verb. This is verified exhaustively: over 281 reachable states (every Settings screen plus every screen along the 16 task rollouts), each visible control is operated and each result classified, with an adversarial battery (nonexistent target, undirected swipe) per screen.

A refused gesture is asserted to change nothing — the anti-cheat.

The interaction benchmark

On top of the world sits a user-in-the-loop measurement apparatus: a simulated human performs an urgent task while an AI assistant watches the rendered screen and may speak. The engine injects one error into the human's plan at a task-progress anchor; the assistant is scored on catching it, on helping recover, and on staying quiet when nothing is wrong. Only the spoken sentence crosses between the two agents.

The progress anchor

Injection fires on a checkpoint sequence over committed application state — the ordered list of state-diffs the apps have actually recorded (an append to the bank's history, a Settings value reaching its committed home). This is path-invariant: two legal routes to the same outcome produce the same anchor, unlike screen state or the widget tree. Every (error × task × anchor) case is admitted only by dry-replay: the deviation grounds, the goal fails, a repair is validated where the world allows one, and the window exceeds the poll cadence. Rejections go to a published admissibility ledger.

The takeover

After injection the engine holds the human on the flawed plan so the error can happen — with a last-chance HOLD beat before any irreversible commit. It releases on a correct detection the human accepts (the same verdict set the scorer uses, imported from one module), or on maximum hold the moment the error commits. An accepted repair is spliced in at the deviation; a held-back update is reported to the human, never dropped.
